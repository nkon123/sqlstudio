## AI 는 SQL 을 실행하지 않는다

이것이 가장 먼저 지키는 규칙이다.

| 경로 | AI 가 쓴 SQL 이 DB 에 닿는가 |
|---|---|
| 앱의 AI 패널 | **아니다.** 답은 화면에 글자로만 나온다. "커서에 넣기 / 문장 바꾸기" 는 에디터 텍스트만 바꾼다. 실행은 사람이 Ctrl+Enter / F5 를 눌러야 한다 (`main.ts` 의 `runStatement` / `runScript` 만 `execute` 를 부른다) |
| 앱의 "튜닝" | 실행계획은 **사용자가 에디터에 쓴 SQL** 로 만든다. AI 답으로 만들지 않는다 |
| MCP 툴 | **아니다.** 임의 SQL 을 받는 툴이 없다. 툴의 SQL 은 앱이 정해 둔 사전 조회이고 AI 입력은 바인드 변수로만 들어간다. 테이블 데이터를 돌려주지 않는다 |
| PL/SQL 분석 | **아니다.** 모델에는 소스 텍스트가 가고 답(JSON)은 파일로만 저장된다. DB 로 가는 것은 단위 목록·소스 사전 조회뿐 (읽기 전용 세션) |
| MCP `explain_plan` | 기본 꺼짐. 켜면 AI 가 쓴 SQL 을 `EXPLAIN PLAN FOR` 로 파서에 넘긴다 — 실행·행 반환은 없다. 그래도 서버로 가는 것이라 관리자가 명시적으로 켜야 한다 |

`crates/sqls-mcp/src/tests.rs` 의 `no_tool_executes_sql` 이 기본 설정의 툴 목록과
입력 스키마(“sql” 인자가 없음)를 고정한다. 툴을 추가하다 이 규칙을 깨면 테스트가 실패한다.

## 세션: 접속당 스레드 하나

OCI 호출은 블로킹이다. UI 스레드나 async 런타임에서 부르면 화면이 멈추고, 런타임 작업자가
묶여 다른 탭까지 느려진다. 그래서 `Session::connect` 가 OS 스레드를 하나 만들고, 그 스레드가
접속과 열린 커서를 소유한다.

- 명령은 `std::sync::mpsc` 로 들어가고, 답은 `tokio::sync::oneshot` 으로 돌아온다.
- 열린 커서(`ResultSet<'static>`)를 스레드가 들고 있다가 `fetch_more` 에 이어서 내준다.
  새 실행이 오면 이전 커서를 닫는다 (커서가 쌓이면 ORA-01000).
- 작업 중 패닉은 `catch_unwind` 로 잡는다. 상태를 믿을 수 없으므로 그 세션만 닫는다.
  호출부는 응답 채널이 끊긴 것으로 `SessionClosed` 를 받는다.

### 취소와 버리기

- `cancel()` 은 작업 큐를 거치지 않고 다른 스레드에서 `dpiConn_breakExecution` 을 바로 부른다.
  서버는 ORA-01013 으로 끝내고, 세션은 계속 쓸 수 있다.
- OCI 의 취소는 TCP 긴급 데이터(OOB)로 간다. 방화벽·NAT·Docker 포트 매핑이 이것을 버리면
  취소가 서버에 닿지 않는다 (통합 테스트에서 실제로 재현했다).
- 그래서 `abandon()` 이 있다: `watch` 채널로 기다리던 호출을 **즉시** 풀고, 작업 스레드는
  붙잡힌 호출이 끝나는 대로 접속을 닫고 사라진다. 화면은 곧바로 새 세션을 연다.
  앱은 취소 후 5초가 지나도 그대로면 이것을 제안하고, MCP 서버는 시간 상한을 넘기면 자동으로 한다.

## 읽기 전용은 두 겹

1. `sql::is_read_only` — 주석·문자열을 건너뛰는 렉서로 첫 단어가 SELECT/WITH 이고
   `FOR UPDATE` 가 없는지 본다.
2. 서버 — 실행할 때마다 `ROLLBACK; SET TRANSACTION READ ONLY` 로 트랜잭션을 연다.
   1을 빠져나간 쓰기(예: 함수 안의 DML)도 서버가 ORA-01456 으로 막는다.

권한 자체를 SELECT 만 가진 계정으로 쓰는 것이 가장 확실하다. 위 두 겹은 그 위의 안전장치다.

## SQL 분석 (`sql.rs`)

DB 에 묻지 않고 텍스트만 보고 한다. 접속 없이 테스트할 수 있고 빠르다.

- `scan_code` 가 `--`, `/* */`, `'...'`(`''` 이스케이프), `q'[...]'`, `"식별자"` 를 건너뛴다.
  분리·판정·바인드 추출이 모두 이것 위에서 돈다. 문자열 속 `;` 나 `:` 에 속지 않는다.
- 스크립트 분리는 SQL*Plus 규칙이다. 일반 SQL 은 `;`, PL/SQL 블록과 단위(CREATE PROCEDURE 등)는
  한 줄짜리 `/` 에서 끝난다. `EXEC x` 는 `BEGIN x; END;` 로 바꾼다. SQL*Plus 명령은 보내지 않는다.
- 위치는 UTF-8 바이트다. 화면(JS)은 UTF-16 이라 `api.ts` 의 `utf16ToByte` / `byteToUtf16` 으로
  바꾼다. 한글이 섞인 SQL 에서 오류 위치가 어긋나지 않게.

## 결과 가져오기

- 첫 페이지만 가져온다 (기본 500행, 배열 fetch 와 prefetch 를 같은 크기로).
- 그리드는 보이는 행만 DOM 으로 그린다. 끝에서 두 화면 안쪽으로 스크롤하면 `fetch_more` 를 부른다.
- 셀은 문자열로 보낸다. NUMBER 의 정밀도를 잃지 않고, 화면은 바로 쓴다. CLOB 은 셀당 4000자에서 자른다.

## 자동완성

키 하나마다 불리므로 원칙은 **"DB 에 묻지 않는다"** 이다.

```
에디터 (completion.ts)          단어 시작·'.'·구절 키워드 뒤에서만 부른다. 이어 치는 글자는 화면에서 거른다
   │  커서 앞뒤 2만 자 + 바이트 위치
   ▼
complete 명령 (src-tauri)       캐시 읽기 잠금만 잡고 sqls_core::complete::complete
   │  모자란 것(missing)이 있으면 메타 세션으로 채우기 — 최대 300ms 기다림
   ▼
sqls_core::complete            토큰화 → 문장 경계 → 쿼리 블록 → 테이블 참조 → 구절 → 후보 점수
   └ SchemaCache               객체·컬럼·PK·FK·동의어·패키지 멤버 (프로필마다 하나)
```

- **문장 경계**: `;`, 한 줄짜리 `/`, 빈 줄. PL/SQL 블록 안이면 앞의 `BEGIN`/`THEN` 등을 떼고 본다.
- **쿼리 블록**: 커서를 감싸는 괄호 중 `SELECT`/`WITH` 로 시작하는 것. 블록마다 FROM/JOIN/INTO/UPDATE/USING
  뒤의 테이블을 모은다. 바깥 블록의 테이블도 범위에 넣되(상관 서브쿼리) 점수를 낮춘다.
- **구절**: 블록 안, 같은 깊이에서 커서 앞의 마지막 구절 키워드. 함수 괄호 안(`NVL(`)은 바깥 구절을 따른다.
  `INSERT INTO t (` 는 컬럼 목록으로 따로 본다.
- **점수**: 접두 일치 > 단어 경계 > 머리글자 > 포함. 여기에 구절별 가중치(컬럼 자리면 컬럼, 테이블 자리면
  테이블)와 PK·FK 가중치를 더한다. 수만 개를 훑는 루프는 할당 없이 점수만 먼저 매기고, 상위 200개 밖으로
  밀려날 점수는 글자를 만들지도 않는다.
- **캐시 적재**: 메타 세션(읽기 전용, 작업 세션과 별개)이 단계별로 읽고 단계마다 반영한다.
  11g 사전 뷰는 느리다 — 제약 × 제약 컬럼 조인은 DB 에서 2~4초, 따로 읽어 Rust 에서 이으면 1초.

## PL/SQL 디버거 (`debug.rs`)

`DBMS_DEBUG` 는 세션 두 개로 돈다.

```
대상 세션  initialize → debug_on → [사용자 블록] → debug_off      ← 사용자 블록 실행 중 서버에서 멈춘다
제어 세션  attach_session → synchronize / continue / get_value / set_breakpoint …
```

- 대상 세션의 실행은 블로킹이라 대상 `Session` 스레드에서 돌리고, 제어는 다른 `Session` 으로 한다.
  세션 모델이 그대로 쓰인다 (멈춘 대상은 그냥 "오래 걸리는 호출" 이다).
- 사용자 블록을 `debug_on … debug_off` 로 감싸 **같은 호출 안에서** 끈다. 따로 부르면 앱이 죽었을 때
  세션이 디버그 상태로 남아 패키지를 잠근다 (실제로 겪었다). 줄 번호가 밀리지 않게 한 줄에 붙인다.
- 대상은 `set_timeout(900)` + `nodebug_on_timeout`: 제어가 사라지면 900초 뒤 디버그 없이 끝까지 돈다.
  `Debugger` 의 `Drop` 은 두 세션을 `abandon` 한다.
- `DBMS_DEBUG` 의 레코드(runtime_info, program_info)는 SQL 로 바인드할 수 없어서 익명 블록 안에서
  스칼라 OUT 바인드로 풀어 낸다. 상수(break_next_line 등)도 시작할 때 서버에서 읽는다.
- 4000바이트 넘는 VARCHAR2 OUT 은 LONG 이 되어 숫자 대입이 PLS-00382 가 난다. 그래서 4000 으로 맞추고,
  긴 값(백트레이스)만 `l_` 이름으로 LONG 바인드한다.
- 프레임 번호는 스택 절대 깊이 (0 = 현재). 시작하면 한 번 step-into 해서 첫 줄에서 멈춘다.
- 디버그 정보 여부는 `ALL_PLSQL_OBJECT_SETTINGS.PLSQL_DEBUG` 로 본다 (11g XE 에 ALL_PROBE_OBJECTS 가 없다).
- 디버거는 사용자가 쓴 블록만 돌린다. AI 경로와는 이어져 있지 않다.

## PL/SQL 분석 (`crates/sqls-analyze`)

작은 로컬 모델은 문맥이 짧고(4~8K), 긴 입력에서 앞을 잊고, 이름을 지어낸다. 그래서 세 가지를 나눴다.

1. **자르기는 기계가 한다** (`plsql.rs`, `chunk.rs`). 주석·문자열(`q'[...]'` 포함)을 건너뛰는 렉서 위에서
   PROCEDURE/FUNCTION 의 머리·선언부·본문을 찾고, BEGIN/IF/LOOP/CASE … END 짝을 스택으로 맞춘다 (CASE 식의 END,
   `END IF` / `END LOOP` / `END CASE` 구분). 본문의 `;` 마다 깊이를 기록해 두었다가, 한도를 넘는 서브프로그램은
   깊이 1(본문 바로 안의 문장 끝)에서 먼저 자르고, 한 문장이 크면 그 안으로 내려간다. 중첩 서브프로그램은 바깥 조각에서
   한 줄 표시로 바꾸고 따로 조각을 만든다. 한 SQL 문(긴 커서)이 한도를 넘으면 `flow::sql_cuts` 의 자리를 쓴다 — 괄호 깊이 p 에서
   절·CTE·JOIN 은 깊이 `10+2p`, 쉼표·AND/OR 는 `11+2p` 로 주어 PL/SQL 문장 경계(1~9)를 다 쓴 뒤에만, 바깥 절부터 쓰이게 했다.
   자른 뒤에는 이웃 조각끼리 한도 안이면 합치고, 아주 작은 조각은 한도의 125% 까지 붙인다. 여러 조각에 걸친 SQL 은 조각 문맥에
   `sql_outline`(맨 바깥 절과 줄 범위)과 문장 전체의 사실을 넣고, 요약 단계에서 SQL 하나로 모은다(`UnitResult.sql_summaries`).
   11g XE 의 SYS 에서 wrap 안 된 171개 단위(OWA_UTIL·HTP·STANDARD 등)로
   검증했다: 구조 경고 0, 서브프로그램 머리 일치, 한도를 넘는 조각 0.
2. **사실은 기계가 뽑는다** (`facts.rs`). 테이블 CRUD(INSERT INTO, UPDATE, DELETE [FROM], MERGE INTO … USING, FROM 목록·JOIN,
   `EXTRACT(x FROM d)` 같은 함수 안 FROM 은 뺀다), 호출 후보(이름 사슬 + `(` 또는 문장 처음 + `;`; 내장 함수, 선언된 지역
   이름·컬렉션 원소·레코드 필드, 형식 자리는 뺀다), 동적 SQL, 트랜잭션 제어, 예외. 통합 분석의 뼈대는 이것만 쓴다.
3. **모델은 의미만 말한다** (`llm.rs`). 프롬프트에 정적 사실을 넣고 요약·단계·규칙·위험만 묻는다. 답은 JSON 스키마로 묶고
   (지원하지 않는 서버가 400 을 내면 스키마 없이 다시), 고쳐 읽고(펜스, 끝 쉼표, 똑똑한 따옴표, 잘린 답 닫기, 생각 블록),
   필드 이름·모양이 달라도 느슨하게 받는다(`{"step": …}`, 문자열 목록). 고친 것은 `llm.repaired` 에 남는다.

SQL 문·커서 흐름(`flow.rs`)은 조각이 아니라 **서브프로그램 전체** 토큰에서 한 번에 뽑고, 문장은 시작 줄로, 커서는 선언
(없으면 처음 쓰인) 줄로 조각에 나눠 담는다. 루프 변수·FETCH/SELECT INTO 변수 → 커서 묶음을 만든 뒤, DML 문 안에서
`R.컬럼`, 묶인 변수(컬렉션 `v(i)` 포함), `CURRENT OF` 를 찾아 잇는다. 커서 루프 안인데 루프 변수를 직접 쓰지 않는 DML 은
`loop body` 로 약하게 잇는다 (부정확할 수 있다는 뜻으로 따로 표시). 패키지 전역·바깥 서브프로그램의 커서는 `KnownCursors`
로 넘겨 읽는 테이블을 붙인다. `EXECUTE IMMEDIATE` / `OPEN … FOR` 의 문자열 상수는 다시 렉싱해 테이블을 뽑는다
(`'INSERT INTO ' || v_tab` 처럼 변수가 끼면 그 자리는 모른다).

저장(`store.rs`)은 조각마다 파일 하나, 임시 파일 → 이름 바꾸기. `analysis_key` = FNV-1a(조각 코드·문맥·시그니처) + 모델 +
`PROMPT_VERSION` + 언어. 같으면 다시 묻지 않는다 — 이어 하기와 증분 분석이 같은 장치다. 요약(서브프로그램·단위)도 입력 해시로
캐시한다. 소스가 바뀌어 사라진 조각 파일은 단위를 쓸 때 지운다.

통합(`integrate.rs`)은 저장된 `unit.json` 만 읽는다 (모델 없이, 몇 초). 호출 이름 풀기는 안쪽 범위부터:
중첩 → 같은 패키지 → `패키지.이름` 이 자기 패키지 → 같은 스키마의 패키지 → `스키마.단독` → 이름이 하나뿐인 다른 스키마
패키지(동의어로 부른 것). 못 푼 것은 `system`(DBMS_/UTL_ …) 과 `unknown` 으로 남긴다. 순환은 반복형 Tarjan,
시작점(들어오는 호출 없는 공개 서브프로그램·트리거)마다 BFS 로 닿는 곳을 구해 COMMIT 위치와 테이블 영향 범위를 만든다.

## AI 문맥

- 서버 버전을 시스템 프롬프트에 넣는다. 11g 면 12c+ 문법을 쓰지 말라고 구체적으로 적는다.
- 스키마는 탐색기에서 체크한 테이블 + SQL 에 나온 테이블 (`meta::referenced_tables`), 최대 8개.
  `meta::schema_brief` 로 짧게 만든다 — 로컬 모델에서 토큰은 곧 시간이다.
- Ollama 는 네이티브 API 로 `num_ctx` 를 지정한다. 기본값(2~4K)은 긴 문맥을 조용히 잘라 버린다.
- 스트림 중 `idle_timeout_secs` 동안 아무것도 안 오면 끊는다. 재시도는 스트림이 시작되기 전까지만
  (시작된 뒤 재시도하면 같은 글자가 두 번 나간다).
- Anthropic 은 `fallbacks: "default"` 로 안전 분류기 거절 시 다른 모델이 이어서 답한다.
  `stop_reason: "refusal"` 은 화면에 표시한다.
