## 고친 것 — PIVOT 결과 열의 '값의 출처' 가 테이블 열까지 가지 않던 것

PIVOT 으로 만든 열(예: `D20`)에서 '값의 출처' 를 보면 "테이블 열에서 오지 않았습니다" 로 끝났다.

- 이제 PIVOT·UNPIVOT 을 풀어 테이블 열까지 따라간다.
  - **PIVOT 이 만든 열:** 집계(`SUM(sal)`), 조건(`deptno = 20`), 값을 낸 열(`EMP.SAL`), 조건 열(`EMP.DEPTNO`) 이 보인다.
  - **묶는 열:** 집계·FOR 에 쓰지 않아 그대로 지나온 열은 그 테이블 열이다.
  - **UNPIVOT 의 값 열:** IN 의 열들이 어느 이름표의 행이 되는지 보인다. **FOR 열:** 이름표(상수) 다.
- 결과 열 이름은 Oracle 규칙대로 맞춘다 (`값별칭_집계별칭`, 이름표가 없으면 값 그대로 `'CLERK'` → `CLERK`). PIVOT 앞이 인라인 뷰·WITH 여도 그 안까지 들어간다.
- `PIVOT XML … IN (ANY)` 처럼 실행해야 열이 정해지는 것은 따라가지 않는다.

## SQL 포맷 — PIVOT·MERGE 등이 한 줄로 나오거나 모양이 섞이던 것

오른쪽 맞춤(강줄기) 포맷이 다루지 않던 문장이 왼쪽 정렬로 넘어가 모양이 섞이거나, 절 안이 한 줄로 늘어졌다. 여러 Oracle 구문을 점검해 아래를 고쳤다.

- **PIVOT·UNPIVOT:** 집계와 IN 의 값을 SELECT 목록처럼 한 줄에 하나 놓고, FOR 는 첫 집계와 같은 칸에 맞춘다.
- **MERGE:** `USING`·`ON`·`WHEN … THEN` 을 절 키워드처럼 맞추고, 갈래 안의 `UPDATE … SET … WHERE` · `DELETE WHERE` · `INSERT … VALUES` 는 한 칸 들인 문장처럼 놓는다. 전에는 `DELETE` 가 앞 줄 끝에 붙기도 했다.
- **키워드 사이의 힌트:** `MERGE /*+ APPEND */ INTO`·`INSERT /*+ … */ INTO` 를 알아본다 (전에는 줄이 엉켰다).
- **INSERT ALL·FIRST:** INTO 마다 한 줄, `WHEN … THEN`·`ELSE` 아래는 한 칸 들인다.
- **CREATE TABLE·VIEW·MATERIALIZED VIEW … AS SELECT:** 머리를 한 줄로 쓰고, 쿼리는 오른쪽 맞춤으로 쓴다.
- **LOG ERRORS INTO … REJECT LIMIT:** 한 줄로 둔다.
- **재귀 WITH 의 `SEARCH … SET`·`CYCLE … SET`:** 다음 줄에 한 줄로 둔다 (전에는 SET 을 UPDATE 의 SET 으로 보고 줄을 잘못 나눴다).
- `GROUPING SETS`·`ROLLUP`·`CUBE`·`MULTISET`·`XMLTABLE` 도 키워드 대소문자 설정을 따른다.
- `WITH FUNCTION`(안에 PL/SQL 본문이 있는 12c 문장)은 포맷하지 않는다. 다른 PL/SQL 블록처럼 안내만 한다.
- MODEL 절·MATCH_RECOGNIZE·JSON_TABLE 의 COLUMNS 는 아직 절 안을 한 줄로 둔다.
