## 값 추적 — "이 값은 어떻게 나왔나"

**결과 그리드에서 셀을 우클릭하고 '이 값은 어떻게 나왔나 (값 추적)' 를 고르면, 그 행의 그 값을 만든 문장을 찾아 이 행의 키로 다시 계산한다.** 분석 결과(PL/SQL 정적 분석만 해도 된다)가 있어야 한다.

- 셀의 열을 테이블 열로 풀고, 그 행의 키(PK, 없으면 고유 인덱스) 값을 결과에서 찾는다. 키 열이 결과에 없으면 넣으라고 알린다.
- 그 열에 값을 넣는 문장마다 원본 쿼리를 이 키로 다시 돌린다. 다루는 문장은 다음과 같다.
  - INSERT … SELECT
  - INSERT … VALUES: 커서 레코드 `R.COL` 은 커서 쿼리로, SELECT INTO 로 받은 변수는 그 SELECT 로 거슬러 간다.
  - MERGE 의 UPDATE·INSERT 갈래
  - UPDATE … SET: `(a, b) = (SELECT …)` 도 다룬다.
- 다시 계산한 값이 지금 값과 같으면 **✓ 재현됨** 으로 표시하고 맨 위에 둔다. 다르면 두 값을 함께 보인다.
- 이 키로 값이 나오지 않으면, 조인 조건은 그대로 두고 **거르는 조건마다 몇 행이 통과했는지** 보인다(예: `✕ 0/3 D.STATUS = 'OK'`).
- 값이 나오면 **그 값을 만든 원본 행과 그 행의 키** 를 보인다. '거슬러 오르기' 를 누르면 그 원본 행의 값이 어떻게 들어왔는지 한 단계 더 따라간다.
- 값을 모르는 PL/SQL 변수(ORA-00904)가 조건에 있으면 그 조건을 빼고 넓게 본다. 변수 값을 넣고 다시 돌릴 수도 있다.
- 'AI 로 설명' 은 추적 결과를 AI 패널에 보내 풀어 달라고 한다. 조회한 값이 들어 있어 **로컬 모델에만** 보낸다.
- DB 에는 여기서 만든 SELECT 만 보내고, 보내기 전에 문장 종류를 다시 확인한다. 질의 하나는 10초까지 돌리고, 넘으면 취소한다.
- **운영 DB 로 표시한 접속과 실행 중인 세션에서는 돌리지 않는다.** 만든 SQL 과 바인드 값만 보이니 복사해 확인한다.

## AI 하네스 — 작은 로컬 모델(Qwen 3.5 4B 등)에 맞춤

**모델을 키우는 대신, 넣는 양을 줄이고 단계를 나누고 답을 검사해 구체적인 오류로 다시 묻는다.**

- **문맥 예산**: 로컬 모델은 num_ctx 의 60% 와 8,000 토큰 중 작은 값까지만 넣는다. 넘치면 다음 순서로 줄인다.
  1. 컬럼 많은 테이블은 관련 컬럼만
  2. 내 쿼리 예시
  3. 문법 안내
  4. 테이블

  대화 기록은 최근 2번만 원문으로 보내고 그 앞은 SQL 만 남긴다. 답 위에 `약 2,140/8,000 토큰` 처럼 보인다. 설정 → AI 의 '문맥 예산' 에서 바꾼다.
- **캐시 재사용**: 시스템 프롬프트를 늘 같게 두고, 할 일·스키마·문법 안내는 사용자 메시지로 옮겼다. 로컬 서버가 앞서 읽은 부분을 다시 써서 첫 글자가 빨리 나온다.
- **생각 모드 자동**: 로컬 모델의 SQL 생성·설명·중간 단계는 생각을 끄고 temperature 0.2 로 보낸다. 튜닝·오류 수정은 모델 기본값을 쓴다. 같은 말을 되풀이하면 끊고 생각을 끈 채 다시 묻는다. 생각 조절을 모르는 모델이면 빼고 다시 보낸다.
- **답의 SQL 검증**: 버전에 없는 문법(11g 의 FETCH FIRST 등)을 앱 안에서 먼저 보고, 서버에서 DBMS_SQL.PARSE 로 **파싱만** 한다. 실행도, 트랜잭션도, 결과 그리드도 건드리지 않는다. 걸리면 오류와 그 테이블의 전체 컬럼을 주고 2번까지 고쳐 묻는다. 답 아래에 `✓ 서버에서 파싱 확인 · 1번 고침` 처럼 보인다. 운영 DB 에서는 서버 확인을 하지 않는다.
- **테이블 고르기**: SQL 생성에서 테이블을 지정하지 않았으면, 질문 낱말을 테이블·컬럼 이름과 주석에서 찾아 후보를 만든다. AI 가 먼저 그 후보 중에서 고르게 한 뒤 SQL 을 쓰게 한다(고르기와 쓰기를 나누면 컬럼을 덜 지어낸다).
- **내 쿼리 예시**: 서버 파싱을 통과한 AI 의 SQL 을 '커서에 넣기'·'문장 바꾸기' 로 에디터에 넣으면 질문과 함께 이 PC 에 쌓는다. 비슷한 질문에 1~2개를 예시로 넣는다. 같은 사용자·같은 DB 의 것만 쓰고, 로컬 모델에만 쓴다. 설정 → AI → 하네스 에서 끄거나 지운다.
- **모델 측정**: 공급자 설정의 '모델 측정' 이 속도, JSON 형식 지원, 생각 모드, 모델 문맥 크기를 재서 저장한다. 하네스가 이 값으로 단계를 조절한다(초당 8토큰보다 느리면 중간 단계를 건너뛰고 고치기는 1번만).
- **평가 도구(개발자용)**: `cargo run -p sqls-llm --example eval -- --model qwen3.5:4b` 로 `evals/` 의 사례를 모델에 돌려 첫 답·고친 뒤 통과율과 시간을 표로 낸다. 프롬프트·카드·생각 설정을 바꿀 때 숫자로 비교한다. 이 PC 의 qwen3.5:4b 로는 첫 답 8/11, 고친 뒤 10/11 이 통과했다(앱 안 판정 기준).
