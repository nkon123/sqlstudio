## 분석 중에 다른 탭의 방향키·입력이 늦던 것

분석을 돌리는 동안 결과 그리드에서 셀을 고르고 방향키를 눌러도 선택이 움직이지 않던(또는 한참 뒤에 움직이던) 것.

- 원인: 분석 중 단위가 하나 끝날 때마다 분석 화면의 단위 목록 전체를 다시 그렸다. 정적 분석은 단위가 1초에 수십 개씩 끝나, 단위가 수천 개면 화면이 목록 그리기에 묶여 다른 탭의 입력까지 밀렸다.
- **분석 중 목록 다시 그리기를 모아서 0.5초에 한 번만** 한다.
- 목록의 '분석한 때' 칸 날짜 서식을 행마다 새로 만들던 것을 한 번 만들어 다시 쓴다 (3,000행에서 15ms → 4ms, 느린 PC 일수록 차이가 크다).

## 시작이 느릴 때 원인 찾기

0.5.31 의 시작 시간 기록에 그 앞 구간을 더했다. 로그(설정 > 정보 > 로그 폴더의 `sqlstudio.log`)의 `시작(화면 앞)` 줄:

`문서 받음 · main.js 받기 · 모듈 실행 끝 · 첫 화면 구성 · 시작 작업 시작` — 화면을 불러오기 시작해서 시작 작업까지 어느 구간에서 시간이 걸리는지 (앱 창(WebView2)·디스크·백신 등 환경 탓인지, 화면 코드 탓인지) 가른다.
