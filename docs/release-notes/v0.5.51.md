## 행 추적 — "이 키의 데이터는 왜 없나"

**테이블과 키 값을 넣으면, 그 테이블에 행을 넣는 문장마다 원본을 이 키로 돌려 원본에 있는지, 없으면 어느 조인·조건에서 끊겼는지 보인다.** 도구 메뉴 '행 추적', 명령 검색 "행 추적", 결과 그리드 우클릭 '이 키의 행 추적 (왜 없나)' 에서 연다.

- 에디터의 지금 SQL 에서 테이블과 `키 = '값'` 을 읽어 채운다. 키 값을 모두 찾으면 바로 돈다.
- 지금 이 키의 행이 있는지 먼저 센다.
- 행을 넣는 INSERT·MERGE 마다 결과를 보인다.
  - **✓ 원본에 있음**: 그 문장이 아직 돌지 않았거나, 돈 뒤에 지워졌을 수 있다.
  - **∅ 원본에 없음**: 키를 쥔 테이블부터 조인을 하나씩 더하며 남는 행 수를 센다(예: `ORD_DTL 3건 → + ORD_HDR 0건`). 0이 되는 조인이 끊긴 곳이다. 거르는 조건은 조건마다 통과한 행 수로 보인다.
- MERGE 의 INSERT 갈래는 대상 행이 없을 때 도는 갈래라, 대상과 짝짓지 않고 USING 원본만 이 키로 본다.
- 그 테이블에서 행을 지우는 DELETE 문장도 함께 보인다.
- 조인 단계 진단은 쉼표로 이은 조인(`FROM A, B WHERE …`)만 다룬다.

## 값 추적 — 어디서 왔는지 한눈에

**값을 고치는 법이 아니라 값이 어디서 왔는지를 보인다.**

- 맨 위에 **출처 흐름**이 보인다. 원본 행에서 시작해 거쳐 온 프로시저·문장·식을 지나 지금 보는 값까지 이어지고, 거슬러 오를수록 위로 길어진다.
- 문장 카드는 원본 → 대상 순서로 그린다.
  1. 원본 행
  2. 서브쿼리(인라인 뷰) 층마다
  3. 커서·SELECT INTO
  4. 문장
  5. 대상

  층마다 식, 대상 키가 그 층에서 어떤 식이 되는지, 다시 계산한 값을 보인다. 서브쿼리 안의 조건에 걸렸으면 그 층에서 보인다.
- **NULL 원인 짚기**:
  - 이 열을 빼고 넣는 INSERT 를 찾는다. 그 문장이 이 키의 행을 만드는지도 다시 계산해 본다.
  - 아우터 조인에서 짝이 없어 NULL 이 된 경우를 알린다.
  - 이 키로 값이 안 나오면 어느 조인에서 끊겼는지도 보인다.
- **AI 로 출처 설명**은 고치는 SQL 없이 값이 어떤 길로 왔는지만 설명한다(로컬 모델만). 기다리는 동안 은은하게 흐르는 진행 막대가 보인다.

## 탐색 기록 — 어떻게 타고 들어가 어떤 쿼리를 몇 번 돌렸나

**값 추적·행 추적 창 아래의 '탐색 기록' 에 길을 고른 순서와 DB 에 보낸 쿼리가 차례로 남는다.**

- 지금 어디를 보는지(프로시저·줄·문장·서브쿼리 층)가 머리줄로 나온다. 그 아래에 다음 두 가지가 순서대로 이어진다.
  - 길을 고른 것: 문장을 찾음, 서브쿼리 안으로, 모르는 변수라 조건을 뺌, 조인이 끊겨 멈춤
  - 보낸 쿼리마다 목적, 결과(몇 건·몇 행·오류), 걸린 ms. 누르면 SQL 과 바인드 값이 펼쳐진다.
- 위에 `쿼리 N번 · DB 시간` 이 보이고, '복사' 로 기록 전체를 SQL 과 함께 복사한다.
- 운영 DB·실행 중인 세션에서는 만든 쿼리를 '보내지 않음' 으로 남긴다.
