## 분석 — 한국어 결과에 한자·가나가 섞이지 않게

**한국어로 분석했는데 답에 중국어(한자)·일본어(가나)가 섞여 나오면, 마지막에 한 번 더 물어 한국어로 다시 쓴다.**

- 조각 분석과 서브프로그램·단위·전체 요약 모두. 처음 지시도 "한자·일본어를 쓰지 말고 한국어나 영어 용어로" 로 분명히 했다.
- 다시 쓸 때 코드 이름·SQL·줄 번호는 그대로 둔다. 따옴표 안의 글(코드에 적힌 오류 메시지 등)은 섞인 것으로 보지 않는다.
- 고쳐 썼으면 호출 기록에 남는다 (예: '한자·가나 3자 섞임 → 한국어로 다시 씀').
- **이미 저장된 결과에 섞여 있으면 다음 분석 때 그 조각·요약만 다시 묻는다.** 깨끗한 결과는 그대로 쓴다.

## 분석 — ACP 에이전트에 맞춘 조각 크기와 동시 수

**분석 공급자로 ACP 에이전트(opencode)를 고르면 조각 줄 수를 모델의 컨텍스트 크기로 정한다.**

- ACP 는 컨텍스트 크기를 알려 주지 않아 `opencode models --verbose` 로 읽는다. 에이전트 지시문 몫을 빼고 20~400줄 (컨텍스트 200K 모델이면 400줄).
- 줄 수 칸 옆에 **(자동)**, 마우스를 올리면 근거 (모델 · 컨텍스트 → 줄 수). 직접 바꾸면 그 값을 쓴다.
- **동시** 도 1 → 4 로 (한 에이전트에 대화를 여럿 연다). 다른 공급자로 돌아가면 기본값.
- opencode 가 아닌 에이전트는 크기를 알 수 없어 그대로 둔다.

## 분석 — 사전 대조를 동시에

**사전 대조(사전 의존성과 파서가 다른 곳을 모델에 묻는 단계)를 4개씩 같이 묻는다.** 하나씩 묻느라 ACP 에이전트에서 특히 오래 걸리던 단계다.

- 상태줄에 `사전 대조 3/20: …` 처럼 진행 수.
- 받은 답은 도중에도 저장한다 — 멈춰도 다음에 이어서.
