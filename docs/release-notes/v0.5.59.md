## AI 답의 하네스 단계 칩

**AI 답 위에 하네스가 거친 단계를 칩으로 보인다 — 무엇을 모아 보냈고, 무엇을 건너뛰었고, 답을 어떻게 확인했는지.**

- 일반 공급자: `테이블 · 실행계획 · 문법 카드 · 예시 · 예산 · 질의 · 검증`. 하는 중이면 돌고, 끝나면 ✓, 알릴 것이 있으면 !, 실패면 ✕, 건너뛰면 점선.
- 칩을 누르면 자세히 펼친다 — 고른 테이블과 고른 방법, 넣은 문법 카드, 예산에 맞추느라 줄인 것, 모델·생각·temperature, 처음 답에서 걸린 오류와 고쳐 물은 횟수, 건너뛴 까닭.
- 예전의 '문맥:' 줄과 답 아래 '✓ 서버에서 파싱 확인' 줄은 칩으로 옮겼다. 확인에서 걸렸을 때만 답 아래에도 빨간 줄을 남긴다.

## ACP 에이전트 — 연결 단계와 하네스

**opencode 같은 ACP 에이전트를 쓸 때도 앞뒤는 앱의 하네스가 맡는다.**

- 에이전트를 고르면 대화 칸에 **연결 카드** — 띄우기 · 초기화 · 세션 · 모델·모드 · MCP 를 걸린 시간과 함께. 3초 넘게 걸린 단계는 '가장 오래 걸린 곳' 으로 짚는다.
- 답 위 칩: `실행계획 · 보낸 문맥 · 에이전트 · 검증`. **보낸 문맥** 을 펼치면 보낸 글 전체, **에이전트** 를 펼치면 생각과 도구 호출.
- **튜닝이면 앱이 실행계획(EXPLAIN PLAN)을 만들어 함께 보낸다** — 에이전트가 explain_plan 도구를 부를지에 맡기지 않는다. 편집 탭이 접속해 있어야 한다.
- **답의 SQL 을 일반 AI 처럼 확인한다** (버전 문법 → 서버 파싱, 실행 안 함). 걸리면 같은 대화로 한 번 고쳐 달라고 묻는다.
- **플러그인 에이전트(omo 등)**: 설정 → AI → ACP 에이전트의 **'플러그인 없이 빠르게 시작 (opencode --pure)'** 를 끄면 플러그인의 에이전트를 쓸 수 있다. opencode 는 primary 에이전트를 모드로 내놓으므로 AI 패널의 Mode 칸에서 고르고, 늘 쓰려면 **처음 모드** 에 적는다. 끄면 시작은 다시 느려진다.

## ACP 에이전트로 분석

**도구 → 분석의 공급자 목록에 ACP 에이전트가 나온다.**

- 조각마다 새 대화로, MCP 없이 plan 모드로, 파일·도구를 쓰지 말고 받은 글만 보고 답하게 묻는다. 권한을 물으면 취소한다.
- 외부 전송 확인 창이 뜬다. HTTP 모델보다 느리다 (조각 하나에 수 초). 이미 분석한 조각은 저장된 결과를 다시 쓴다.

## 설정 → 하네스

**AI 질문 하나가 거치는 8단계를 카드로 본다 (새 설정 페이지).**

- 고른 공급자에서 실제로 도는지(늘 · 자동 · 측정값 · 꺼짐)와 그 까닭, 쓰이는 작업, 바꿀 수 있는 설정을 카드마다.
- 작업(SQL 생성 · 튜닝 …)을 누르면 그 작업에 쓰이는 단계만 진하게.
- ACP 에이전트를 고르면 무엇이 달라지는지 — 앱이 맡는 단계와 에이전트가 맡는 단계.
- 테이블 고르기 · 문법 카드 · 내 쿼리 예시 설정은 **설정 → AI** 에서 이 페이지의 카드 안으로 옮겼다.
