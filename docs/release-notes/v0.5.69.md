## Pro*C 도 PL/SQL 처럼

**`.pc` 파일(글에 `EXEC SQL` 과 `#include`·중괄호가 있으면)을 Pro*C 로 보고 코드 탐색을 그대로 쓴다.**

- **색**: C 와 그 안의 `EXEC SQL … ;`(`EXECUTE … END-EXEC;` 포함)를 나눠 칠한다. `EXEC SQL` 이 걸친 줄에는 옅은 바탕, 호스트 변수 `:v_amount` 는 굵게, `#include` 는 흐리게.
- **개요 · 위치 줄 · 접기**: DECLARE SECTION · struct · C 함수(K&R 머리 포함) · 커서 · `EXEC SQL` 문장(OPEN · FETCH · UPDATE · MERGE · EXECUTE …). 위치 줄은 `load_orders › for › if › UPDATE orders`.
- **Ctrl+클릭**: C 함수 호출 → 정의, `OPEN c_ord` → `DECLARE c_ord CURSOR`, `:v_amount` → DECLARE SECTION 의 선언, C 지역 변수 → 함수 안의 선언. `EXEC SQL` 안의 테이블은 DB 에서.
- Pro*C 에서는 키워드 자동 대문자를 끄고(C 코드를 바꾸지 않게), SQL 자동완성은 `EXEC SQL` 안에서만.

## 개요를 쿼리 단위로

**프로시저·함수 아래에 SQL 한 문장씩 — 개요의 '쿼리' 단추로 켜고 끈다 (기본 켬).**

- PL/SQL: SELECT · INSERT · UPDATE · DELETE · MERGE · `FORALL …` · `EXECUTE IMMEDIATE` · `OPEN rc FOR …` · `FOR r IN (SELECT …)` 안의 쿼리. 이름은 `UPDATE orders`, `SELECT order_items` 처럼 대상 테이블로.
- Pro*C: `EXEC SQL` 문장.
- Ctrl+Shift+O 구조 보기에도 같이.

## 소스 탭 이름

- Ctrl+클릭·F4 로 연 소스 탭이 '새 문서 N' 이 아니라 **객체 이름**(`P_CLOSE_DAY`, `PKG_ORDER`)으로. 다음에 켤 때도 남는다.
- 이름이 겹치면 뒤에 `(2)` `(3)`. 이미 연 소스는 그 탭으로 가고, 그 탭을 고쳤으면(●) 두고 새로 연다.
- 다른 이름으로 저장할 때 파일 이름도 `P_CLOSE_DAY.sql`.
