## 고친 것 — 실행계획(Ctrl+E)이 커밋하지 않은 변경을 말없이 롤백하던 것

UPDATE·INSERT 같은 변경을 하고 커밋하기 전에 실행계획을 보면, 그 변경이 말없이 롤백됐다. 실행계획을 만들기 전에 트랜잭션을 통째로 롤백했기 때문이다. 커밋·롤백 단추는 그대로 떠 있어서 변경이 사라진 줄 모르고 커밋할 수 있었다.

- 이제 열린 트랜잭션이 있으면 세이브포인트를 두고 실행계획을 만든 뒤, 그 세이브포인트까지만 되돌린다. 하던 변경은 그대로 남는다.
- 실행계획을 본 뒤에도 트랜잭션 상태를 다시 읽는다.

## 고친 것 — 읽기 전용 접속에서 SELECT 만 해도 커밋·롤백이 뜨던 것

'읽기 전용' 접속 프로필은 서버 쪽에서도 변경을 막으려고 문장마다 `SET TRANSACTION READ ONLY` 를 먼저 실행한다. 이 문장이 트랜잭션을 열어서, 조회만 해도 '커밋 전' 으로 보였다.

- 읽기 전용 접속의 이 트랜잭션은 바꿀 것이 없으므로 '커밋 전' 으로 치지 않는다. 서버 쪽 보호는 그대로다.

## 화면 — 탭과 설정 창

- **탭을 크롬처럼 바꿨다.** 위쪽 모서리를 둥글게 하고, 고른 탭은 아래 편집기와 이어지며 아래 모서리가 바깥으로 휜다. 탭 사이에는 짧은 구분선을 두고, 닫기(×)와 새 탭(+)은 동그란 단추로 했다.
- **설정 창을 정리했다.**
  - 크기를 고정해서 페이지를 바꿔도 창이 들썩이지 않는다.
  - 왼쪽은 아이콘이 달린 목록, 오른쪽 위에는 페이지 제목과 한 줄 설명을 둔다.
  - 소제목마다 카드로 묶고, 카드 안에서는 이름과 입력 칸을 줄 맞춰 놓는다.
  - 접속·AI 페이지는 '접속 프로필 / tnsnames.ora', 'AI 공급자 / Oracle 문법 안내' 로 나눴고, 목록에서 지금 고치는 항목을 표시한다.
- **편집기 밖에서 끌어도 글이 골라지지 않는다.** 메뉴·단추·목록·탭·상태줄을 끌다가 화면 여기저기가 칠해지던 것이다. SQL 편집기·입력 칸·출력·실행계획·구조·AI 대화·오류·값 보기·값의 출처·알림은 전처럼 골라 복사할 수 있다.
